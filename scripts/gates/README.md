# TeamCLI gate scripts

Versioned copies of the gate scripts the TeamCLI seats run during local-fast rounds. They live in this repo under `scripts/gates/`; the running copies live in `~/Code/floor/briefs/teamcli-notes/`; when one changes there, copy it here in the same step.

- `light-check.sh`: the per-batch light check (typecheck + the tests the change touches and the tests of every module that imports a changed one, two hops deep, from a reverse-import graph over `src/` built per check). Every selected file prints its reason (`touched`, `imports <module>`, `matches <module>`, `depth 2`, or `always`). `test/cli-smoke.test.ts` (every command's `--help` and `--json --help` through the real CLI) is selected on every run, with the reason `always`, while it exists. A heavy test file (measured alone and listed with its time in `gate-common.sh`) is selected only when the change touches it; when the dependency selection passes 80 files, depth 2 is dropped and the cut is printed with the reasons. A hub module (more than `HUB_IMPORTERS` direct test importers, default 10) contributes only its own name/path test; the tests it would have pulled in are printed as left to the hub sweep, and the check queues one background sweep of exactly those files in a heavy slot (`hub-sweep.zsh`) and returns, printing the sweep's report and marker paths before it detaches. The non-hub depth-1 additions are a tail capped at `DEPTH1_MAX` files (default 60); the overflow is printed as left to the hub sweep too, with the reason `depth-1 tail over 60`. Takes one of four machine-wide light slots (`light-slot-{1..4}.lock`); never the heavy slots. A slot whose owner pid is gone is reclaimed, never waited on; a live pid's slot is never touched. A hard wall-clock limit for the whole check (`LIGHT_CHECK_MAX_MIN`, default 10) kills the check's own bun tree at the limit — its bun and that bun's children, nothing else — writes `TIMEOUT after <n> min: running <what>`, frees the slot and exits non-zero. The release of the slot ignores INT/TERM/HUP once it starts and frees the slot before it stops the watchdog, and the watchdog frees a slot whose release was cut short while it still holds that check's owner line (a slot another check took meanwhile is left alone). A branch built on an integration branch (`integration/0.5.x`, `p0b-integrator`, or the `GATE_INTEGRATION` list) is compared with the newest merge-base not on `origin/main`, so only the seat's own work is checked.
- `gate-common.sh`: shared helpers (the dependency-aware test selection with the heavy table, the hub threshold, the depth-1 tail cap, the always-selected CLI smoke, the exit-codes filter, the private-patterns scan, and `reclaim_dead_lock`, which reclaims a lock whose owner pid is gone and never touches a live pid's).
- `push-gate.sh`: the gate before a real push to GitHub (compared with `origin/main`).
- `private-patterns.txt` (outside every repo and never committed; `~/Code/floor/briefs/teamcli-notes/private-patterns.txt`, created mode 0600): one extended regex per line, `#` comments. `push-gate.sh` and `light-check.sh` scan the diff's added lines against `GATE_BASE` and the branch's commit messages, printing each hit as `file:line` or `commit:<sha>:<line>` plus the pattern's line number, never the matched text. A hit refuses the push and only warns in the light check; a missing file warns and never fails. `GATE_PRIVATE_PATTERNS` points the scan at another file (tests use a neutral temporary one).
- `hub-sweep.zsh`: the background sweep the light check queues when the hub rule leaves tests out — one run in a heavy machine slot (first free of `heavy-run{,-2,-3}.lock`; a slot whose owner pid is gone is reclaimed first, a live pid's is never touched), never a loop. It writes `hub-sweep/<branch>-<sha>.md` (counts, per-file lines, failures by file with the first error line), sends one line, skips an identical sha and file set already queued or running, releases its heavy slot right after the test loop (before the report and the send), and on red writes a marker chosen by branch: the shared `hourly-suite/RED` only when the swept branch is the integration tip (`integration/0.5.x`, the first entry of `GATE_INTEGRATION`), which stops every merge; any other branch writes `hub-sweep/RED-<branch with / as _>`, which blocks only that branch's merge.
- `hourly-suite.zsh`: one full suite on the integration tip, at most once an hour while a round is
  open (`--loop`, run from an operator seat's own pane, never detached). It skips when the tip is the
  sha the last pass ran on, when another pass holds the hourly lock, or when a heavy slot is held
  (a lock whose owner pid is gone is reclaimed first; a live pid's is never touched);
  otherwise it takes one heavy slot, updates the dedicated `hourly-suite` worktree to the tip, runs
  `bun run ci`, and writes `hourly-suite/<sha>.md` (counts, failures by file and first error line). A
  red result on the integration tip writes `hourly-suite/RED` (tip + failing files): no merge into
  the integration branch until the lead clears it; a red on another ref writes
  `hourly-suite/RED-<ref with / as _>` and blocks only that ref's merge. A run that ends without
  its report is never silence: the EXIT trap writes the report as `NO REPORT: the run ended at
  <time> without results (last log line: …)` plus that ref's RED marker, and the start of every
  pass reports a previous log that still has no report beside it (the wrapper a SIGKILL could not
  trap).

History (2026-10-17): the light check used to compare every branch with `origin/main`, so on the integration branch each check re-ran the whole release delta (74 files, the 160 s exit-codes test unfiltered); with ~13 seats in parallel the machine load reached ~95. Fixed by the merge-base comparison and the four-slot cap.

History (2026-10-17, the first of the round's two owner-approved structural changes): the light check is dependency-aware. A changed `src/` module selects its direct test importers and its name/path test files, plus the same for every src module that imports it, transitive to depth 2, from a reverse-import graph over `src/` computed per check; `test/exit-codes.test.ts` stays the exit-ids rule's alone. `push-gate.sh` uses the same selection, and both scripts log each selected file's reason. CI still runs the full suite.

History (2026-10-17, the second owner-approved structural change): `hourly-suite.zsh` added. The light check cannot see the tests a change does not touch; an hourly full suite on the integration tip covers them while a round is open, and a red run writes `hourly-suite/RED` to stop merges into the integration branch until the lead clears it.

History (2026-10-17, tuning the dependency-aware change): `test/broker.test.ts` measures 963 s alone (the sized claim-lane stress spawns ~2.5k processes), so heavy files are data in `gate-common.sh` (`heavy_tests`: file → measured standalone seconds) and one is selected only when a change touches it; `test/exit-codes.test.ts` (153 s alone in the sweep of every test file) is the exit-ids rule's own and is not in that list. When the dependency selection passes 80 test files, depth 2 is dropped and left to the hourly suite, and both cuts are printed with the selected files' reasons. Re-measured on the three reference changes, original selection → tuned: lobby 26 files / 35 s → 223 files / 519 s (broker skipped, depth 2 dropped, 204 depth-1 files kept); send 26 / 46 s → 64 / 112 s (dependency selection 40, no cap); effort 24 / 32 s → 94 / 219 s (depth 2 dropped, 73 kept). Send is inside the 60–120 s target; the lobby hub change is not — its depth-1 set is 204 files, mostly `src/commands/up.ts`'s direct test importers. (The tuned after-runs also carried 2–3 files that are red at those old commits — tests of later features — not selection cost.)

History (2026-10-17, the hub rule): a module with more than `HUB_IMPORTERS` direct test importers (then default 20, now 10, set at the top of `gate-common.sh`; `exit-codes` and heavy files do not count) contributes only its own name/path test to the light check. Every test it would otherwise have pulled in is printed as left to the hub sweep, and the check queues one background run of exactly those files (`hub-sweep.zsh`: first free of `heavy-run{,-2,-3}.lock` by `mkdir`, one run then exit, never a loop, skipped when an identical sha and file set is already queued or running; `LIGHT_NO_HUB_SWEEP=1` turns the queueing off). The sweep writes `hub-sweep/<branch>-<sha>.md` (counts, per-file lines, failures by file with the first `error:` line), sends one line to the orchestrator, and on red writes a marker chosen by branch: the shared `hourly-suite/RED` only for the integration tip, `hub-sweep/RED-<branch with / as _>` for any other branch (so one branch's red never holds another's merge). Re-measured on the same three changes with the same all-mode harness, light check original → tuned → hub rule, then the sweep: lobby 26 files / 35 s → 223 / 519 s → 144 / 349 s (13 hub modules, 104 tests left out; swept GREEN in 115 s); send 26 / 46 s → 64 / 112 s → 37 / 57 s (1 hub, 27 left out; swept GREEN in 29 s); effort 24 / 32 s → 94 / 219 s → 88 / 181 s (2 hubs, 17 left out; swept GREEN in 20 s). Send is inside the 60–120 s target; lobby and effort are not — their depth-1 long tail (`check.ts`, `list.ts`, `init.ts` on a lobby change) and the ~20-file docs rule dominate, while the hub left-outs now run in the background instead of the check.

History (2026-10-17, tuning the hub rule): `HUB_IMPORTERS` default 20 → 10, and the non-hub depth-1 tail capped at `DEPTH1_MAX` (default 60; the overflow joins the hub sweep's set with the reason `depth-1 tail over 60`). Re-measured on the same three changes with the same all-mode harness (light check / test files / left to the sweep / sweep): at 20, lobby `1823ed82` 349 s / 144 / 104 / GREEN 115 s, send `9ef0a776` 57 s / 37 / 27 / GREEN 29 s, effort `b75d2c1a` 181 s / 88 / 17 / GREEN 20 s; at 10, lobby 217 s / 107 / 143 / GREEN 90 s, send the same 37 files and 27 left-outs, effort 62 s / 43 / 62 / 171 s; at 10 + cap 60, lobby 198 s / 88 / 162 / 101 s, effort 61 s / 43 / 62 / 161 s; at 10 + cap 20, lobby 174 s / 75 / 176 / 199 s. The live defaults (10 and 60) re-count 88 / 37 / 43 test files. The enlarged sweep sets contain files already red at those historical commits — `test/send-resolve.test.ts`, `test/route.test.ts` and `test/send-record-identity.test.ts` do not exist on main, and `test/commands/one-read.test.ts` passes 13/0 standalone on main — so those RED results are historical, not selection cost. Send and effort are inside the 60–120 s target; lobby is not, and its floor stays near 120 s because the ~20-file docs rule, the hub name/path tests and the touched tests sit outside the tail the cap trims.

History (2026-10-17, never silence and no dead locks): a suite run that ends before writing its report — killed, or exited on an error — now leaves a `NO REPORT: the run ended at <time> without results (last log line: …)` report and its ref's RED marker instead of an empty hour: the EXIT trap writes them for anything the wrapper can trap, and the start of each pass sweeps a leftover log with no report beside it (the SIGKILL case) using the sidecar `<sha>.pending` that records the ref and subject. The light slots, the hourly lock and the heavy slots are reclaimed when the owner line's pid is gone (`kill -0` fails): `reclaimed <lock> from dead pid <n> (<owner line>)`, with a live pid's lock never touched — a dead spike branch's light slot had sat four hours. And the light check gets a hard wall-clock limit: at `LIGHT_CHECK_MAX_MIN` (default 10, from the slot) its watchdog kills only its own bun tree, writes `TIMEOUT after <n> min: running <what>`, frees the slot and the check exits non-zero. Stub tests: `hourly-suite.test.zsh` (both no-report paths, killed wrapper and stale log), `lock-reclaim.test.zsh` (dead reclaimed, live and pid-less not; hourly suite and hub sweep wiring), `light-check-limit.test.zsh` (a sleeping fake bun is killed with its child, slot freed, non-zero exit).

History (2026-10-17, a signal inside the release): the light check's slot release now ignores INT/TERM/HUP once it starts and frees the slot before it stops the watchdog, and the watchdog frees a slot whose release was cut short — only while it still holds that check's owner line, so a slot another check took meanwhile is left alone. The window was the watchdog's own TIMEOUT TERM: the release ran with the `exit 143` trap still set, and a TERM landing there aborted it before the rmdir. Stub tests: `light-check-release-race.test.zsh` (a TERM storm inside a paused release leaves the slot freed and the check exits 0; on the pre-fix script the same stub exits 143), `cli-smoke-selection.test.zsh` (the always-selected CLI smoke, existing and touched).
